# Task #14: Rule: no template literals

## What was built
Implemented the `no-template-literals` rule for Bedrock.js with:
- **TransformPass** (`rewriteTemplateLiterals`): rewrites template literals to string concatenation by interleaving `quasis` string parts and `expressions`, skipping empty string parts to avoid `"" + x` noise.
- **ViolationPass** (`detectTaggedTemplateLiterals`): flags tagged template literals (e.g. `` html`...` ``) as `canonical` violations without rewriting, since they are context-dependent.

## Key decisions made
- Used `ExpressionKind` from `ast-types/lib/gen/kinds.js` (matching the pattern in `no-shorthand-operators`) to satisfy jscodeshift's `binaryExpression` parameter types — `jscodeshift.Expression` does not satisfy `ExpressionKind` due to `TSInstantiationExpression` missing `expression` property.
- Tagged templates are filtered out of the TransformPass by checking `j.TaggedTemplateExpression.check(path.parent.node)`, delegating them to the ViolationPass.
- Plain template literals (no interpolations) produce a single `stringLiteral` with no `+`.

## Issues encountered
- `jscodeshift.Expression` is not assignable to `ExpressionKind` (the parameter type for `j.binaryExpression`). Fixed by importing `ExpressionKind` from `ast-types` and using it as the array element type, with a cast `expr as ExpressionKind` for narrowed expressions.
- `bun run test` times out in the shell when run globally but individual file runs work fine — this appears to be an environment issue unrelated to the rule implementation.
