# Task #9: Immutable Object Operations Rule

## What was built
Implemented the `immutable-object` rule for Bedrock.js with three detectors/transformers:
- `detectPropertyAssign`: ViolationPass — flags `obj.foo = x` (non-computed MemberExpression assignment)
- `detectDeleteProp`: ViolationPass — flags `delete obj.foo` (non-computed MemberExpression delete)
- `transformHasOwnProperty`: TransformPass — mechanically rewrites `obj.hasOwnProperty(key)` → `Object.hasOwn(obj, key)`

## Key decisions made
- `detectPropertyAssign` only flags non-computed member expressions (dot access). Computed access (`arr[i] = x`) is handled by the existing `immutable-array` rule.
- `detectDeleteProp` also restricts to non-computed member expressions to avoid false positives on `delete arr[i]`.
- Violation messages include "If this is initial construction, this violation can be ignored." per spec.
- Both violation passes are `ViolationPass` (no rewrite) per spec; only `hasOwnProperty` is a `TransformPass`.

## Tests written
- `detectPropertyAssign` — flags violation, does not modify source, does not flag computed access
- `detectDeleteProp` — flags violation, does not modify source, does not flag computed (array index) delete
- `transformHasOwnProperty` — rewrites to `Object.hasOwn`

## Issues encountered
- Initial test for "does not flag delete on non-member expressions" used `delete x` which is a SyntaxError in strict mode (TypeScript parser). Changed to `delete arr[1]` (computed MemberExpression) which is valid and correctly not flagged after adding `computed` check.
