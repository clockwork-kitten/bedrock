# Task #8: Immutable Array Operations Rule

## What was built
Implemented the `immutable-array` rule for Bedrock.js covering all array mutation and array additional rules from SPEC.md.

## Key decisions made
- **TransformPasses** (mechanical rewrites): `transformPush`, `transformUnshift`, `transformSort`, `transformSparseArrays`
- **ViolationPasses** (flag only): `detectSortNoComparator`, `detectPop`, `detectShift`, `detectSplice`, `detectIndexedAssign`, `detectArrayConstructor`
- `push`/`unshift` transforms only apply when the call is a standalone `ExpressionStatement` (not embedded in an expression) and the array is an `Identifier` — this avoids name conflicts and complex cases
- Generated name for transformed arrays is `arrayName + "2"` (simple, consistent)
- Multi-arg `push`/`unshift` are handled by spreading all args
- Fixtures kept to single-operation cases to avoid naming collision issues with the simple naming scheme

## Tests written
12 tests in `src/rules/immutable-array/index.test.ts`:
- transformPush: rewrites single-arg push to spread
- transformUnshift: rewrites single-arg unshift to spread
- transformSort (x2): wraps sort(comparator) with spread copy; does not modify sort() without comparator
- transformSparseArrays: replaces holes with undefined
- detectSortNoComparator (x2): flags violation; does not flag sort with comparator
- detectPop: flags pop() violation
- detectShift: flags shift() violation
- detectSplice: flags splice() violation
- detectIndexedAssign: flags array[i] = x violation
- detectArrayConstructor: flags both Array(n) and new Array(n)

## Issues encountered
- TypeScript required `ExpressionKind` import from `ast-types` for array element types
- `getLocation` helper couldn't be typed on `ASTNode` (TypeScript error), inlined loc extraction like other rules
- Initial fixture for push had two push calls which revealed the transform generates `items2` for both (doesn't chain names) — simplified fixtures to single operation
