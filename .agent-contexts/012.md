# Task #12: No Shorthand Operators Rule

## What was built
Implemented the `no-shorthand-operators` rule for Bedrock.js, covering:
- `compoundAssignToExplicit`: TransformPass that rewrites `+=`, `-=`, `*=`, `/=` to explicit `x = x op n` form
- `updateExpressionToExplicit`: TransformPass that rewrites standalone `x++`, `x--`, `++x`, `--x` (as ExpressionStatements) to `x = x + 1` / `x = x - 1`
- `detectUpdateExpressionInExpression`: ViolationPass that flags `x++`/`--x` when used as expressions (where the return value is consumed), since those cannot be mechanically rewritten without a temp variable

## Key decisions made
- UpdateExpression as a standalone ExpressionStatement is auto-fixed (TransformPass); used as an expression (e.g. `const y = x++`) is flagged as a violation (ViolationPass) since a mechanical rewrite would change semantics
- Used `as unknown as` casts to bridge jscodeshift's `PatternKind | MemberExpressionKind` vs `ExpressionKind` type mismatch in `j.assignmentExpression` and `j.binaryExpression` — this is a known jscodeshift typing limitation

## Issues encountered
- jscodeshift type mismatch: `AssignmentExpression.left` is `PatternKind | MemberExpressionKind` but `j.binaryExpression` expects `ExpressionKind`. Used `as unknown as ExpressionKind` cast.
- `j.assignmentExpression` first arg expects `PatternKind | MemberExpressionKind` but `UpdateExpression.argument` is `ExpressionKind | PatternKind`. Used `Parameters<...>[1]` cast pattern.
