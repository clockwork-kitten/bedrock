# Task #6: async/await over .then()/.catch() transformer rule

## What was built
A reporter-only detection rule that flags `.then()`, `.catch()`, and `.finally()` call expressions as violations without rewriting the AST. Extended the type system to support `ViolationPass` — a pass that collects violations rather than modifying source.

## Key decisions made
- `ViolationPass` receives a `ViolationCollector` as a third argument, keeping the signature consistent with `TransformPass` while adding the collector
- `createViolationCollector()` is a private factory in `transform.ts` — callers never construct it directly
- `violationPasses` is optional on `TransformOptions` (defaults to `[]`) so existing callers need no changes
- `violations: Violation[]` added to `TransformResult` — always present (empty array when no violation passes run)
- `transform.test.ts` existing tests continue to pass because `violations` is always returned (just empty)
- Tests written directly (not via `runFixtures` helper) so they can assert both source identity AND violation contents

## Files changed
- `src/transformer/types.ts` — added `Violation`, `ViolationCategory`, `ViolationCollector`, `ViolationPass` types; updated `TransformOptions` and `TransformResult`
- `src/transformer/transform.ts` — added `createViolationCollector()`, threads violation passes through, returns violations in result
- `src/transformer/index.ts` — re-exports new types
- `src/testing/fixture-runner.ts` — added `runViolationFixturePairs` and `runViolationFixtures` helpers
- `src/testing/index.ts` — exports `runViolationFixtures`
- `src/rules/async-await/index.ts` — `detectPromiseChains` ViolationPass implementation
- `src/rules/async-await/index.test.ts` — 5 tests covering then/catch/finally detection and clean code

## Tests written
- `src/rules/async-await/index.test.ts`:
  - detects .then() chains and does not rewrite source
  - detects .catch() chains and does not rewrite source  
  - detects .finally() chains and does not rewrite source
  - reports no violations for clean async/await code
  - reports line and column for violations

## Issues encountered
- The `runViolationFixtures` helper returns violations from the test callback but can't easily assert on them from the fixture runner level; wrote tests directly instead for violation assertions
- Existing `transform.test.ts` tests needed no changes because `violations` defaults to `[]`
