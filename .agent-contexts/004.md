# Task #4: var/let → const transformer rule

## What was built
Implemented the `var-to-const` transformer rule for Bedrock.js. The rule:
- Converts `var` declarations to `const` if the binding is never reassigned, or `let` if reassigned
- Converts `let` declarations to `const` if the binding is never reassigned
- Handles multi-declarator statements (if any binding in the statement is reassigned, the whole declaration stays `let`)

## Key decisions made
- Used `path.scope.path` to get the enclosing scope's AST node, then searched within it for `AssignmentExpression` or `UpdateExpression` referencing the binding name
- Typed `scope` as `ScopeLike` (local type alias) since `jscodeshift.Scope` doesn't exist in the `@types/jscodeshift` namespace
- Excluded `src/__fixtures__` from `tsconfig.json` to prevent `noUnusedLocals` errors in intentionally simple fixture files
- Added `export {}` to fixture files to make them isolated modules (prevents cross-file `Cannot redeclare` TS errors)

## Tests written
- 5 fixture-based tests via `runFixtures("var-to-const", [varToConst])`:
  - `var-basic`: var → const
  - `var-reassigned`: var → let
  - `let-not-reassigned`: let → const
  - `let-reassigned`: let stays let
  - `multi-declarator-mixed`: mixed declarators, any reassigned keeps let

## Issues encountered
- `jscodeshift.Scope` type doesn't exist in `@types/jscodeshift` — worked around with a local `ScopeLike` type alias
- Fixture `.ts` files triggered `noUnusedLocals` and redeclaration errors — fixed by excluding fixtures from tsconfig and adding `export {}` to each file
