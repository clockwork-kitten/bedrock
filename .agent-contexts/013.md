# Task #13: No Classes / No This Rule

## What was built
Implemented the `no-classes` rule for Bedrock.js. This is a ViolationPass-only rule that flags `class` syntax (both declarations and expressions) and `this` expressions, directing developers to use factory functions and explicit parameter passing instead.

## Key decisions made
- ViolationPass only (no rewrite) — as specified, transforming classes to factory functions is a complex structural change not suitable for automated rewriting
- Split into three separate `ViolationPass` exports: `detectClassDeclaration`, `detectClassExpression`, `detectThisExpression` — each handles one node type
- Shared `locOf` helper for safe location extraction (mirrors pattern from `no-arrow-functions`)
- Fixtures have identical input/output since there's no rewrite — violation-only fixture format

## Files changed
- `src/rules/no-classes/index.ts` — three ViolationPass exports for ClassDeclaration, ClassExpression, ThisExpression
- `src/rules/no-classes/index.test.ts` — tests for all three passes including negative test
- `src/__fixtures__/no-classes/class-declaration.input.ts` / `.output.ts` — class declaration fixture
- `src/__fixtures__/no-classes/class-expression.input.ts` / `.output.ts` — class expression fixture
- `src/__fixtures__/no-classes/this-expression.input.ts` / `.output.ts` — this expression fixture

## Tests written
- `detectClassDeclaration > flags class declaration without modifying source`
- `detectClassExpression > flags class expression without modifying source`
- `detectThisExpression > flags this expression without modifying source`
- `detectThisExpression > does not flag code without this`

## Issues encountered
- Initial negative test for `detectThisExpression` used the class-declaration fixture which contains `this.count` and `this.name` references — causing false positives. Fixed by using an inline code string with no `this`.
