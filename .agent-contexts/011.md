# Task #11: Rule: no ternary, no switch, no short-circuit control flow

## What was built
Six violation-only detection passes for Bedrock.js control flow patterns:
- `detectTernary` — flags `ConditionalExpression` (ternary `x ? a : b`)
- `detectSwitch` — flags `SwitchStatement`
- `detectLogicalOrDefault` — flags `LogicalExpression` with `operator === "||"`
- `detectLogicalAndExec` — flags `LogicalExpression` with `operator === "&&"`
- `detectNullishCoalescing` — flags `LogicalExpression` with `operator === "??"`
- `detectOptionalChain` — flags `OptionalMemberExpression` and `OptionalCallExpression`

All are `ViolationPass` only (no auto-transform). Source is unchanged; violations are reported with `canonical` category.

## Key decisions made
- Violation-only (no TransformPass) as specified — rewrites require new variable names and structural changes that need human judgment
- `OptionalCallExpression` included alongside `OptionalMemberExpression` for `?.` detection (e.g. `obj?.method()`)
- Inlined loc extraction inline per path.node (matching existing rule patterns) rather than using a helper, to satisfy TypeScript's ASTNode type constraint

## Issues encountered
- Initial implementation used a `locOf(node: ASTNode)` helper but `ASTNode` type does not have `loc` property in jscodeshift's type definitions. Resolved by inlining the loc extraction pattern directly in each `forEach` callback, consistent with how other rules in the codebase do it.
