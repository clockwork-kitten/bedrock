# Task #7: Loops Rule for Bedrock.js

## What was built

Implemented the full loops/iteration rule set for Bedrock.js as specified in SPEC.md.

**TransformPasses (mechanical rewrites):**
- `forOfToIndexed` — rewrites `for...of` loops to indexed `for (let i = 0; i < array.length; i++)`, with a `const item = array[i]` binding prepended to the body
- `forInToIndexed` — rewrites `for...in` loops to `Object.keys(obj)` + indexed `for`, inserting `const keys = ...` before the loop and `const key = keys[i]` inside
- `whileToFor` — rewrites `while (cond)` to `for (; cond;)`

**ViolationPasses (flag only, no auto-rewrite):**
- `detectDoWhile` — flags `do...while` as `canonical` violation
- `detectForEach` — flags `array.forEach()` as `canonical` violation; does NOT flag `map`, `filter`, `reduce`
- `detectBreak` — flags `break` statements
- `detectContinue` — flags `continue` statements

## Key decisions made

- **for-in parent handling:** The `forInToIndexed` pass needs to insert a `const keys = ...` statement before the for loop. It handles both `BlockStatement` and `Program` parents using splice, falling back to wrapping in a block for edge cases (e.g. for-in as body of an if statement).
- **StatementKind typing:** jscodeshift's `Statement` type doesn't directly satisfy `StatementKind` from ast-types. Imported `StatementKind` directly from `ast-types/lib/gen/kinds.js` to type `newBody` correctly.
- **Non-block body of for-of/for-in:** If the loop body is not a block (e.g. a single statement), it's wrapped in a `blockStatement` to allow prepending the element/key binding.
- **Permitted methods:** `map`, `filter`, `reduce` are explicitly NOT flagged per the SPEC.md principled exception.

## Issues encountered

- `jscodeshift.Statement` is not assignable to `ast-types` `StatementKind` — resolved by importing `StatementKind` directly from `ast-types/lib/gen/kinds.js`.
- `forInToIndexed` initially wrapped top-level for-in in an extra block because the parent was `Program` not `BlockStatement` — fixed by also handling `j.Program.check(parent.node)`.
- Output fixtures needed to be checked against actual transform output (extra blank line added by jscodeshift between statements, `for (; cond; )` spacing).
