# Task #18: Test suite: fixture-based input/output tests for all rules

## What was built

A reusable fixture-based test harness for Bedrock.js rule implementors. The harness loads `*.input.*` / `*.output.*` file pairs from `src/__fixtures__/<ruleName>/`, runs each input through the transformer with the provided passes, and asserts the output matches exactly (trimmed). Infrastructure only — no fixtures added yet.

## Key decisions made

- **Exported helpers for testability:** Rather than testing `runFixtures` via side-effect (which violates Vitest's "no `describe` inside `it`" rule), the internal helpers (`collectFixturePairs`, `detectParser`, etc.) were exported so they can be unit tested directly.
- **`runFixturePairs` split from `runFixtures`:** Allows tests to pass in-memory `FixturePair[]` arrays without hitting the filesystem, enabling mock-based testing of the full transformation assertion path.
- **`vi.mock("node:fs")`:** Used to avoid disk I/O in harness tests while still exercising real transformation logic.
- **Added `@types/node` and `"types": ["node"]` to tsconfig:** Required for `node:fs` and `node:path` imports to typecheck.

## Files changed

## Tests written

- `src/testing/fixture-runner.test.ts`
  - `stripExtension` — removes extensions correctly
  - `isInputFile` — identifies `.input.*` files
  - `fixtureNameFromInputFile` — extracts fixture name
  - `findOutputFile` — finds matching output, throws when missing
  - `detectParser` — returns `ts` for `.ts`/`.tsx`, `babel` for `.js`
  - `collectFixturePairs` — builds pairs from mocked dir listing, throws on orphan
  - `runFixturePairs` (integration) — matching case passes; mismatched case assertion throws

## Issues encountered

- Vitest does not allow `describe()` calls inside `it()` blocks — required splitting collection logic (`collectFixturePairs`) from registration logic (`runFixturePairs`) so tests could call the latter at the module top level.
